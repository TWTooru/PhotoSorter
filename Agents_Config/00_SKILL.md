\# C# 任務視覺化交付協議 (C# Delivery Protocol)



\## 核心意圖

本協議旨在將複雜的 .NET / C# 開發任務轉化為透明、可追蹤且具備增量備份習慣的結構化流程。



\## 執行階段與查核點 (Workflow Stages)



1\. \*\*intake (需求攝入)\*\*:

&#x20;  - 確認開發目標與 C# 專案背景。

&#x20;  - 解析輸入參數，評估是否涉及 UI 變更或底層邏輯重構。



2\. \*\*analysis (架構分析)\*\*:

&#x20;  - 對標現有架構是否符合相依性注入 (DI) 原則。

&#x20;  - \[專家掛載] 參照 `uiux.md`，若涉及介面，必須初步評估響應式佈局的需求。



3\. \*\*plan (路徑規劃)\*\*:

&#x20;  - 產出開發計畫清單。

&#x20;  - \[強制任務] 若涉及介面開發，必須在此輸出「使用者路徑 (User Journey)」。

&#x20;  - 定義預期使用的 C# 12+ 語法特性。



4\. \*\*execution (邏輯實作)\*\*:

&#x20;  - \[代碼約束] 嚴格執行 `coding.md` 規範（PascalCase、Primary Constructors、非同步處理）。

&#x20;  - \[視圖約束] 實作時遵循 `uiux.md` 的 MVVM 模式與 8pt 網格系統。



5\. \*\*verification (驗證與除錯)\*\*:

&#x20;  - \[品質把關] 依照 `debug.md` 排查 `NullReferenceException` 與 `IDisposable` 實作。

&#x20;  - \[防禦性保存] 驗證成功後，主動提示進行 Git Commit，紀錄此功能增量。



6\. \*\*delivery (結構化交付)\*\*:

&#x20;  - 總結修改的類別、介面與 UI 組件。

&#x20;  - 提供後續整合或單元測試的建議。



\## 輸出規則

\- 每一階段必須至少產生一筆「進行中 (in\_progress)」與一筆「已完成 (completed)」的事件紀錄。

\- 嚴禁跳過 `verification` 階段直接進入 `delivery`。
